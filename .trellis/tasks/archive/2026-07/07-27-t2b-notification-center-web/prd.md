# W2 通知中心（Web 前端）

> **轨**：Track W ｜ **依赖**：**C-2 冻结**（T2a 通知事件契约），**非** T2a 完整交付
> **性质**：纯前端。Web 与 Desktop 共用同一套组件（路线图 §4.2）。

## Goal

落地站内通知中心：导航栏铃铛与未读角标、通知列表页、已读管理与筛选。

## Context

- 一期 Out of Scope 列了「完整通知中心」
- 事件模型与查询 API 来自 T2a（C-2）
- 前端规范重点：`runtime-query-guidelines.md`（轮询）、`interaction-guidelines.md`、`api-query-contracts.md`
- query key 前缀：`notificationKeys`（路线图 §9.2 已分配）
- 独占路径：`apps/web/src/features/notifications/**`（新建）

**并行前提**：C-2 冻结后即可用 mock 开发，不等 T2a 交付。禁止自行发明字段名（路线图 §8.4）。

## Requirements

### R1 未读角标与铃铛

- AppShell 导航栏展示通知铃铛与未读计数角标
- 未读计数走轮询更新，轮询策略遵守 `runtime-query-guidelines.md`：
  - 明确轮询间隔与停止条件（页面不可见时应停止）
  - 不因轮询导致明显的资源浪费
- 角标在未读为 0 时不显示
- 大数量时角标显示上限（如 `99+`）

### R2 通知快览

- 点击铃铛展开最近通知的快览面板
- 快览展示有限条数，提供「查看全部」入口跳转列表页
- 快览内可直接标记已读

### R3 通知列表页

- 分页展示，按时间倒序
- 按已读状态筛选（全部 / 未读 / 已读）
- 按严重级别筛选
- 筛选与分页状态进 URL（可分享、可刷新保持），按 `type-safety.md` 做参数校验与非法值兜底
- 每条通知展示：严重级别、标题、正文、发生时间、关联实体入口

### R4 关联跳转

- 通知关联到任务或运行记录时，提供跳转入口
- 关联实体已被删除时，入口显示为不可用并说明原因，不跳到 404

### R5 已读管理

- 标记单条已读
- 批量标记已读（选中多条）
- 全部标记已读（需确认，避免误操作）
- 删除单条
- 清空已读（需确认）
- 操作后正确失效相关 query cache（未读计数、列表、快览三处都要更新）

### R6 状态与错误恢复

- loading / empty / error 状态齐全
- 空状态文案有意义（区分「从未有通知」与「当前筛选无结果」）
- 错误展示包含 traceId
- 操作失败时不留下错误的乐观更新状态

### R7 Desktop 兼容

- 不直接读取 Wails 全局对象
- Desktop 原生通知的开关入口若出现在本页面，通过 D1 的 `useDesktopCapability` 判断可用性，浏览器环境显示禁用态与说明

### R8 测试

- 测业务逻辑：筛选参数解析、query key 与缓存失效、已读状态转换、空状态判定
- **不测**页面结构与 CSS
- 轮询停止条件有测试

## Notes

- **禁止自行发明字段名**：mock 数据严格按 C-2 定义（路线图 §8.4）
- **缓存失效是最容易漏的地方**：未读计数、列表、快览三处共用数据源，任一操作都要三处同步
- 轮询是本页面唯一的持续资源开销，停止条件必须明确，别做成永不停止的定时器
