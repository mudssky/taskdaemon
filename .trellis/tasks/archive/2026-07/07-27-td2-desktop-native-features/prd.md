# D3 Desktop 原生增量能力

> **轨**：Track D（路线图中标识为 D3）｜ **依赖**：**C-5 冻结**（D1 capability 契约）
> **性质**：Web 套壳之上的原生增量，跨 Go/Wails 与前端边界层。

## Goal

实现「桌面端 = Web 端套壳 + 一些功能」中的「一些功能」：托盘、开机自启、单实例、窗口状态持久化。

## Context

- 定位来源：路线图 §4.2 —— Desktop 差异全部收敛在能力边界层，业务代码不分叉
- capability 接入方式来自 D1（C-5），本任务不发明新的注册模式
- Wails 侧代码：`services/taskdaemon-go/internal/desktop/`
- 错误码前缀：`DESKTOP_*`（路线图 §9.1 已分配）
- 独占路径：`internal/desktop/tray*.go`、`autostart*.go`、`window_state*.go`

**与 T5 的边界**：T5 是把 **taskdaemon 服务**注册为系统服务（无界面、开机常驻）；本任务的自启动是把 **Desktop 应用**加入登录项。两者机制、作用域、用户预期都不同，不可混用。设计阶段必须在文档中说清区别，避免用户困惑。

## Requirements

### R1 系统托盘

- 托盘图标常驻，展示服务运行状态（运行中 / 已停止 / 异常）
- 托盘菜单至少提供：显示主窗口、快速查看运行状态、退出
- 关闭主窗口时可选择最小化到托盘而非退出，行为可配置
- 平台不支持托盘时优雅降级，不影响应用启动

### R2 开机自启（Desktop 应用）

- 可开关的登录项注册，覆盖 macOS / Windows / Linux
- 状态可查询：当前是否已注册
- 权限不足或平台不支持时返回 `DESKTOP_*` 结构化错误并说明原因
- 卸载应用后不留残余登录项（或在文档中说明清理方式）
- **与 T5 的系统服务安装明确区分**，UI 与文档中都不能让用户混淆

### R3 单实例

- 重复启动时激活已有实例窗口，不启动第二个进程
- 单实例检测跨平台可用
- 检测机制在异常退出后不会永久锁死（残留锁文件/端口可自愈）

### R4 窗口状态持久化

- 记忆窗口位置、大小、最大化状态
- 显示器配置变化（拔掉外接屏）后窗口不会落在不可见区域
- 状态存储位置在用户数据目录下，与配置文件分离
- 状态损坏时回退到默认布局，不阻塞启动

### R5 能力接入

- 全部能力按 C-5 定义的 binding 注册模式接入，**不改注册框架**
- 前端通过 D1 的 `useDesktopCapability` 消费，不直接读 Wails 全局对象
- 相关开关出现在设置页时，浏览器环境显示禁用态与说明

### R6 配置

- 托盘行为、自启动、最小化到托盘等开关按 C-1 契约分级并落配置
- 配置结构追加到 `internal/config/types.go` 尾部（append-only）

## Acceptance Criteria

- [ ] 托盘图标常驻，状态展示正确（运行中/已停止/异常三态）
- [ ] 托盘菜单提供显示主窗口、查看状态、退出
- [ ] 关闭主窗口的行为可配置（最小化到托盘 vs 退出）
- [ ] 平台不支持托盘时优雅降级，应用仍可启动
- [ ] macOS 开机自启注册/注销可用
- [ ] Windows 开机自启注册/注销可用
- [ ] Linux 开机自启注册/注销可用（或明确记录不支持的桌面环境）
- [ ] 自启动状态可查询
- [ ] 权限不足/不支持时返回 `DESKTOP_*` 结构化错误并说明原因
- [ ] **文档与 UI 明确区分「Desktop 自启动」与「T5 系统服务」**
- [ ] 重复启动激活已有窗口，不产生第二个进程（三平台验证）
- [ ] 异常退出后单实例机制可自愈，不永久锁死（用测试或手动验证证明）
- [ ] 窗口位置、大小、最大化状态在重启后恢复
- [ ] 显示器配置变化后窗口不落在不可见区域
- [ ] 窗口状态损坏时回退默认布局，不阻塞启动
- [ ] 全部能力按 C-5 注册模式接入，未修改注册框架
- [ ] 前端无任何直接 Wails 全局对象引用
- [ ] 浏览器环境相关开关显示禁用态与说明
- [ ] 配置项按 C-1 分级
- [ ] 三平台手动验证有记录（含系统版本）
- [ ] `pnpm test:go`、`pnpm vet:go`、`pnpm typecheck`、`pnpm lint` 全绿

## Out of Scope

- 应用内自动更新

- 系统服务安装（归 T5）
- Desktop 原生通知（归 D2）
- 多窗口支持

## Notes

- **与 T5 的混淆是本任务最大的产品风险**：用户看到两处「自启动」会不知道该开哪个。UI 文案与文档必须写清楚
- 单实例的锁残留是常见坑：进程被 kill -9 后要能自愈
- 窗口落在不可见区域是笔记本外接显示器场景的高频问题，必须处理
- 四项能力彼此独立，可以拆成四个 PR 分批合并，降低集成风险
