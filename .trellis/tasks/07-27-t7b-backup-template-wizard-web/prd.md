# W3 备份模板向导（Web 前端）

> **轨**：Track W ｜ **依赖**：T7a 的模板与渲染 API 契约
> **性质**：纯前端。Web 与 Desktop 共用同一套组件（路线图 §4.2）。

## Goal

落地备份任务的创建向导：选择模板 → 填写参数 → 预览命令 → 生成任务草稿并提交到既有任务创建流程。

## Context

- 模板定义与渲染 API 来自 T7a
- 任务创建走**既有**任务 CRUD 接口，本向导只负责生成草稿（T7a 已约定「任务只有一条创建路径」）
- 前端规范重点：`form-testing-guidelines.md`（复杂表单分层）、`interaction-guidelines.md`
- query key 前缀：`templateKeys`（路线图 §9.2 已分配）
- 独占路径：`apps/web/src/features/tasks/templates/**`（新建）

## Requirements

### R1 向导流程

- 多步向导：选择模板 → 填写参数 → 预览确认 → 提交
- 每步可返回上一步且**保留已填内容**
- 当前步骤与进度可见
- 中途离开有未保存提示

### R2 动态表单渲染

- 表单控件由 T7a 返回的**参数定义动态生成**，前端不硬编码某个模板的字段
- 支持 T7a 定义的全部参数类型（字符串、数字、布尔、枚举选项、路径、密钥引用）
- 每个参数展示帮助文本
- 必填项有明确标记
- 新增后端模板时前端**无需改代码**即可渲染（本任务的关键设计目标）

### R3 校验与错误

- 客户端做基础校验（必填、类型、格式），规则来自参数定义
- 服务端字段级错误映射到对应表单字段，不是笼统 toast
- 校验规则不宽于服务端

### R4 命令预览

- 提交前展示 T7a 渲染的命令预览
- 敏感值在预览中以掩码展示（T7a 已保证掩码，前端不得反向解掩码）
- 预览可复制，便于用户在终端先行验证
- 预览与最终生成的任务定义一致，不做二次加工

### R5 提交与衔接

- 用户确认后，把草稿提交到**既有任务创建接口**，不走独立创建路径
- 创建成功后跳转到任务详情或列表，并给出成功反馈
- 创建失败时保留向导内容，允许修正后重试
- 提交后正确失效任务列表的 query cache

### R6 入口

- 在任务列表页提供「从模板创建」入口，与现有「新建任务」并列
- 入口不喧宾夺主，普通创建仍是主路径

### R7 状态与错误恢复

- loading / empty / error 状态齐全
- 模板列表为空时有明确说明
- 错误展示包含 traceId

### R8 测试

- 测业务逻辑：动态表单的参数定义 → 控件映射、校验规则生成、payload mapper、步骤状态机
- **不测**页面结构与 CSS
- 「新增模板无需改前端代码」用测试证明（喂一个测试模板定义，验证能正确渲染）

## Notes

- **动态渲染是本任务的核心设计目标**：如果新增一个后端模板需要改前端代码，说明设计失败
- 命令预览是用户建立信任的关键 —— 用户要能看懂将要执行什么，再决定是否创建
- 不要为了「一键完成」而绕过既有任务创建接口，那会造成两条创建路径长期分叉
