# G5 AG-UI 完整体验（Codex 式）

> **轨**：Track G ｜ **依赖**：**G4**（agent-web 骨架）
> **性质**：在 G4 基础上扩展，不重构。前端为主，可能需要 G2/G3 补少量能力。

## Goal

把 G4 的最小可用会话前端提升为完整的 Codex 式 Agent 工作台：thinking 与 HITL、steering、工作区与产物、断线续传、会话管理。

## Context

- G4 已交付会话列表、流式消息、工具调用时间线
- 本任务实现 G0 功能分级表中标为「**G5 增强**」的全部项
- 契约来自 C-3；若需要 C-3 未定义的事件或端点，**必须先回到 G1 扩展契约**，不得在前端绕过
- 独占路径：`apps/agent-web/**`（与 G4 共用，但 G4 完成后本任务接手）

## Requirements

### R1 thinking 与中间态

- 展示 agent 的推理过程，**按 `capabilities.thinking` 决定是否渲染**
- 可折叠，默认收起，不干扰主消息流
- runtime 不提供时按 C-3 的处置方式，**不伪造**

### R2 HITL（Human-in-the-loop）

- agent 请求人工确认时，UI 展示决策点与上下文
- 用户可批准 / 拒绝 / 修改后继续
- 等待人工输入时运行状态明确（不是「卡住了」）
- 超时行为明确（若有）

### R3 Steering

- 运行中注入补充输入，不中断当前 run
- steering 消息在时间线上位置正确，与普通消息可区分
- **`capabilities.steering === false` 时该功能优雅隐藏**，不显示无效按钮

### R4 工作区与产物（**仅 coding profile**）

- **前置条件**：`capabilities.workspaceBinding === true`。为 false 时整块 UI 不渲染，且会话仍完全可用（路线图 §5.5）
- 会话绑定工作目录（cwd），当前工作区可见
- 文件变更预览：agent 修改了哪些文件
- diff 预览：变更内容可读
- 工作区路径受 G2 的沙箱根限制，越界在 UI 上有明确说明
- **只读预览**，不在本应用内提供文件编辑

### R5 断线重连与续传

- 流式连接断开后自动重连
- 按 C-3 定义的补发语义续传事件，不丢失、不重复
- 重连过程对用户可见，不静默
- 无法续传时明确告知并提供刷新恢复路径

### R6 会话管理

- 会话重命名
- 会话搜索（按标题与内容，具体范围按 C-3 支持的能力）
- 会话 fork（从某个消息分叉出新会话）
- 归档策略：归档、恢复、清理
- 会话列表的筛选与排序

### R7 契约扩展纪律

- 若本任务需要 C-3 未覆盖的能力，流程是：**回 G1 扩展契约 → G2/G3 实现 → G5 消费**
- **禁止**在前端绕过契约直连 runtime 或自行发明事件类型
- 契约扩展必须回写路线图 §9 的变更行

### R8 测试

- 测业务逻辑：HITL 状态机、steering 时序、断线续传的事件去重与补齐、fork 逻辑、搜索过滤
- **不测**页面结构与 CSS
- 断线续传的事件去重是最容易出 bug 的地方，测试要充分

## Notes

- **断线续传的事件去重是本任务的头号技术风险**：重连后重复渲染或丢事件都会直接毁掉用户信任
- HITL 的「等待中」状态必须显眼 —— 用户不知道在等他，会以为程序挂了
- 本任务功能多，建议按 R1~R6 拆成多个 PR 分批合并，每批独立可用
- 遇到契约不够用时**回头改契约**，这比在前端打补丁便宜得多
