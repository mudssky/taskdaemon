# T1a 配置写入 API 契约与后端实现

> **轨**：Track T ｜ **依赖**：T0（音频收口）
> **契约冻结点**：**C-1 配置写入 API 形状**。W1（设置页）、T4、T5、T6、D3 都消费本任务产物。

## Goal

冻结 taskdaemon 的配置写入 API 契约并实现后端能力：哪些配置可写、写入后是热生效还是需重启、校验失败长什么样、reload 结果怎么回。

**这是设置页能做的前提**，也是所有「配置可在页面编辑」类需求的统一入口。

## Context

当前状态：

- `GET /api/config/audio` 只读，无写入能力（T0 遗留的未闭合项之一）
- 配置加载顺序、env 覆盖、runtime reload 机制见 `.trellis/spec/backend/configuration-runtime-guidelines.md`
- 配置结构：`internal/config/types.go`、`defaults.go`、`load.go`
- reload 现有入口：`internal/app/reload.go`
- 错误码前缀：`CONFIG_*`（路线图 §9.1 已分配）
- 独占路径：`internal/httpapi/config_routes.go`、`config_dto.go`、`runtime_config.go`

**为什么依赖 T0**：T0 的音频设置页写配置需求会验证本契约的第一个真实用例，且两者改同一批文件。T0 先收口，本任务再统一契约。

## Requirements

### R1 配置分级（契约核心）

把配置项分成三级并逐项归类：

| 级别 | 含义 | 页面可编辑 |
|---|---|---|
| **热生效** | 写入后立即生效，无需重启 | ✅ |
| **需重启** | 写入后落盘，重启才生效 | ✅，但必须明确提示 |
| **仅配置文件** | 安全敏感、路径类、发布部署类，不开放 API 写入 | ❌，只读展示状态或提示配置文件位置 |

- 分级结果必须逐项文档化，不能靠代码推断
- 新增配置项时必须显式指定级别，缺省不得默认为「热生效」

### R2 写入 API 形状

- 按 section 写入（如 `PUT /api/config/<section>`），不做整份 YAML 覆盖
- 支持部分更新（只提交要改的字段），语义明确：未提交字段保持不变
- 请求体不接受「仅配置文件」级别的字段，提交则拒绝并指明字段名
- 响应必须返回：写入后的有效配置、哪些字段已热生效、哪些字段需重启

### R3 校验与错误

- 校验失败返回**结构化字段级错误**：字段路径 + 原因，不是一句话字符串
- 区分「格式非法」「取值越界」「与其他配置冲突」「该字段不可写」
- 全部使用 `CONFIG_*` 稳定错误码 + traceId
- 校验在写入前完成，不出现「部分写入成功」

### R4 热生效与 reload

- 热生效字段写入后立即在运行时生效，无需重启进程
- reload 结果可观测：哪些子系统重新加载成功、哪些失败
- reload 失败不能让服务进入不可用状态，必须能回到写入前的运行配置
- reload 行为沿用 `internal/app/reload.go` 现有机制，不另起一套

### R5 落盘与并发

- 写入落盘到配置文件解析结果对应的路径，与 CLI `--config` 解析一致
- 落盘原子（先写临时文件再替换），避免写一半崩溃导致配置损坏
- 并发写入有保护，不出现互相覆盖
- 保留原文件的注释与格式（若技术上不可行，必须在文档中明确说明并给出用户提示）

### R6 安全

- 敏感值（token、密码、哈希）**永不明文回显**，只返回「是否已配置」状态
- 写入敏感值时只落哈希或加密形式，与 T0 的 Token 处理方式一致
- 配置写入操作记入日志，但脱敏，沿用 `internal/httpapi/redaction.go`
- 写入 API 走管理员认证，不对入站机器 Token 开放

### R7 契约文档化（C-1 冻结产物）

- 配置分级表、API 形状、请求/响应 DTO、字段级错误结构、reload 结果结构写入 `.trellis/spec/backend/configuration-runtime-guidelines.md`
- API 形状同步写入 `.trellis/spec/backend/api-contracts.md`
- 冻结完成后回写路线图 §9 表格的产物路径

## Acceptance Criteria

- [ ] 全部现有配置项完成三级分类并写入文档
- [ ] 按 section 的写入 API 可用，支持部分更新
- [ ] 未提交字段保持不变（用测试证明）
- [ ] 提交「仅配置文件」级字段被拒绝，错误指明具体字段名
- [ ] 响应返回有效配置 + 已热生效字段 + 需重启字段
- [ ] 校验失败返回字段路径 + 原因的结构化错误
- [ ] 四类校验失败（格式/越界/冲突/不可写）可区分
- [ ] 校验失败时零写入，无部分成功
- [ ] 热生效字段写入后立即生效（用测试或手动验证证明）
- [ ] reload 结果可观测，逐子系统展示成功/失败
- [ ] reload 失败不导致服务不可用，可回到写入前配置
- [ ] 落盘路径与 CLI `--config` 解析一致
- [ ] 落盘原子，中断不损坏配置文件
- [ ] 并发写入有保护
- [ ] 注释保留行为已实现或已明确文档化其限制
- [ ] 敏感值不明文回显，只返回已配置状态
- [ ] 敏感值落盘为哈希或加密形式
- [ ] 配置写入日志脱敏
- [ ] 写入 API 走管理员认证，机器 Token 无法调用
- [ ] 全部错误路径返回 `CONFIG_*` 稳定错误码与 traceId
- [ ] 后端 route 测试覆盖成功路径与主要失败路径
- [ ] C-1 契约写入 spec，路线图 §9 产物路径已回写
- [ ] `pnpm test:go`、`pnpm vet:go` 全绿
