# T7a 备份任务模板后端 API

> **轨**：Track T ｜ **依赖**：**C-1 冻结**（T1a 配置写入契约）
> **性质**：纯后端。向导 UI 归 W3。

## Goal

提供「备份任务模板」的后端能力：定义一组常见备份场景的模板，把用户填写的参数渲染成一个合法的 runner 任务草稿。

## Context

一期 Out of Scope 列了「备份模板（pgBackRest / pg_dump 等）」，来源：`.trellis/tasks/archive/2026-05/05-14-cross-platform-scheduler-daemon/prd.md`。

- runner 与任务模型：`internal/runner/`、`.trellis/spec/backend/scheduler-runner-guidelines.md`
- runner 白名单已在一期交付，模板只能生成白名单内的 runner 任务
- 错误码前缀：`TEMPLATE_*`（路线图 §9.1 已分配）
- 独占路径：`internal/template/**`（新建）、`internal/httpapi/template_*`（新建）

**核心约束**：模板只**生成任务草稿**，不直接创建任务、不直接执行。创建仍走既有任务 CRUD，保证一条创建路径。

## Requirements

### R1 模板模型

- 模板有稳定标识、名称、描述、适用场景说明
- 模板声明自己的参数：名称、类型、是否必填、默认值、校验规则、帮助文本
- 参数类型是有限枚举（字符串、数字、布尔、枚举选项、路径、密钥引用），不是自由类型
- 模板声明它生成哪种 runner，且必须在 runner 白名单内

### R2 首批模板范围

至少覆盖：

- **PostgreSQL 逻辑备份**（`pg_dump`）：连接参数、输出路径、压缩选项、保留策略
- **SQLite 文件备份**：源路径、目标路径、是否校验完整性
- **通用脚本备份**：用户自定义命令 + 常用参数骨架

不追求覆盖全部备份工具；pgBackRest 等复杂工具留待有真实需求时新增。

### R3 模板查询 API

- 列出全部模板（含参数定义）
- 按标识查询单个模板详情
- 统一 envelope、traceId、`TEMPLATE_*` 稳定错误码

### R4 渲染 API

- 输入模板标识 + 参数值，输出**任务草稿**（不落库）
- 草稿结构与既有任务创建 API 的请求体兼容，前端可直接提交给任务创建接口
- 渲染前校验参数：必填、类型、取值范围、路径合法性
- 校验失败返回字段级结构化错误（与 C-1 的错误结构保持一致，不发明第二套）
- 渲染结果包含可读的命令预览，供用户确认

### R5 安全（重点）

- 渲染出的命令**必须**在 runner 白名单内，越界返回 `TEMPLATE_RUNNER_UNSUPPORTED`
- 参数值做**命令注入防护**：用户输入不得逃逸出参数位置构造任意命令
- 数据库密码等敏感参数不明文进入任务定义；采用引用现有凭据配置的方式，且引用方式与 C-1 敏感配置约定一致
- 渲染日志脱敏，命令预览中的敏感值以掩码展示

### R6 可扩展性

- 新增模板只需新增一个模板定义文件，不改渲染框架
- 模板定义与渲染逻辑分离

## Acceptance Criteria

- [ ] 模板模型定义完成，参数类型为有限枚举
- [ ] 模板声明的 runner 必须在白名单内，违反在注册期被拒绝
- [ ] `pg_dump` 模板可用，参数完整
- [ ] SQLite 文件备份模板可用
- [ ] 通用脚本备份模板可用
- [ ] 模板列表 API 返回完整参数定义
- [ ] 模板详情 API 可用
- [ ] 渲染 API 输出的草稿与既有任务创建 API 请求体兼容（用测试证明）
- [ ] 渲染不落库，不创建任务
- [ ] 参数校验覆盖必填、类型、范围、路径合法性
- [ ] 校验失败返回字段级结构化错误，结构与 C-1 一致
- [ ] 渲染结果含可读命令预览
- [ ] 越界 runner 返回 `TEMPLATE_RUNNER_UNSUPPORTED`
- [ ] **命令注入防护有效**：恶意参数值无法构造额外命令（用测试证明，含分号、反引号、`$()`、换行等载荷）
- [ ] 敏感参数不明文进入任务定义
- [ ] 命令预览中敏感值以掩码展示
- [ ] 渲染日志脱敏
- [ ] 新增一个模板无需修改渲染框架（用新增测试模板证明）
- [ ] 后端 route 测试覆盖成功路径与主要失败路径
- [ ] `pnpm test:go`、`pnpm vet:go` 全绿

## Notes

- **命令注入是本任务的头号风险**：用户参数最终会进入 shell 命令，防护必须在设计阶段定死，测试必须覆盖典型载荷
- 渲染出草稿而不直接创建任务，是为了保证「任务只有一条创建路径」，不要为了少一次点击破坏这个约束
- 首批模板宁少勿滥，模板框架的可扩展性比模板数量重要
